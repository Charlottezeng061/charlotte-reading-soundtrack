Dynamic Reading Soundtrack

Project overview

Dynamic Reading Soundtrack is a browser-based audio instrument that lets readers combine a book genre with an atmosphere. The two sound layers create background audio that readers can adjust to suit their interpretation of a story.

Instead of searching for a new playlist whenever the mood changes, readers can preview sounds, choose a combination and return to their book. The interface keeps these choices visible so readers can make occasional changes while reading.

Design scenario

Dynamic Soundtrack-er

The scenario asks for an ongoing soundtrack for an activity or environment, shaped by occasional but meaningful user input. I apply this to reading, where a story can move between different moods while the reader's attention remains on the book.

Reader agency is central to my response. The instrument does not analyse the book or decide how a scene should feel. Readers choose the genre and atmosphere themselves, allowing different interpretations of the same story.

For example, a reader can keep Fantasy selected while changing the atmosphere from Calm to Dark as a chapter becomes more tense. Their input changes the soundtrack because their reading of the story has changed.

From concept to final instrument

My initial concept explored a continuously evolving soundtrack with changes in rhythm, texture and atmosphere. Through prototyping, I narrowed this into a more manageable interaction: combining two recorded audio layers.

Assignment 2 explored six prototypes across soundtrack control and soundtrack guidance. These helped me consider how much control to give users and how to explain unfamiliar interactions without filling the interface with instructions.

The final instrument brings together direct selection, short previews and controlled randomness. Each category contains four sounds, providing variation within a simple interface.

This changes the scope of the original concept. The final version selects and combines existing recordings rather than generating notes or continuously changing musical parameters.

Core interactions

Choosing and previewing sounds

Users select one genre and one atmosphere. The genres are Fantasy, Mystery, Romance and Sci-Fi. The atmospheres are Calm, Dark, Magical and Nostalgic.

Clicking a sound button selects it and starts a preview of up to six seconds. This lets users hear a layer individually before playing it together with the other selection.

Double-clicking the same button moves to its next sound. The label “Sound 1 / 4” shows which of the four recordings is selected. Selected buttons keep a filled background so the current combination remains clear after the preview ends.

Playing both layers

The central Play button starts the selected genre and atmosphere together. It changes to a Pause icon during playback. The volume slider adjusts the overall sound level.

The current soundtrack display sits above the selections. It shows the chosen combination and changes its status when audio is previewing, playing or paused.

Random, Repeat and Reset

Random chooses different recordings within the selected genre and atmosphere. It keeps the selected category buttons unchanged. This allows users to try another combination without losing the mood they have chosen.

Repeat loops the two soundtrack layers. Its button changes appearance when enabled. Each recording loops independently according to its own duration.

Reset stops playback, restores Fantasy and Calm, returns all categories to their first sound, sets volume to 50% and turns Repeat off.

Extended technique: Random

I use controlled randomness to introduce variation while keeping the reader's choices meaningful. Random selects recordings within the chosen categories rather than selecting from the entire sound collection.

For each selected category, the code chooses one of the other three recordings. This avoids immediately choosing the sound that is already selected.

The following shows the same selection technique used in the instrument: 

function randomClip(currentClip) {
  // Move forward by one, two or three clips.
  const offset = Math.floor(Math.random() * 3) + 1;

  // Keep the clip number between 1 and 4.
  return ((currentClip - 1 + offset) % 4) + 1;
}

Math.random() provides a value between 0 and 1. Multiplying by three and rounding down creates three possible offsets. The remainder operator wraps the result back into the four available clip numbers.

This supports experimentation within a chosen mood. A reader can keep Fantasy and Calm selected while hearing a different pair of recordings.

How the code supports the interaction

The instrument uses HTML, CSS and vanilla JavaScript. HTML provides the sound buttons, playback controls, volume slider and guide. CSS handles layout, themes and visual states. JavaScript connects these controls to audio playback and updates the interface.

The selected genre and atmosphere are stored as variables. A separate collection stores the current clip number for each category. Keeping these values separate allows Random to change the recording without changing the selected category.

Two Audio objects play the soundtrack layers, while a third handles previews. The preview can therefore play one recording independently. The volume slider converts its percentage into a value between 0 and 1 for the audio volume property.

Click and double-click need separate handling. A short delay allows the code to distinguish a single click from the beginning of a double-click, helping prevent conflicting preview and clip-change actions.

Design system

Colour and typography

The instrument uses warm brown (#3f2e11) and beige (#dfd4b8). Night mode uses a brown background with light text, while day mode reverses this relationship.

Fraunces gives the main title a literary character. Outfit is used for buttons and supporting information, keeping repeated controls easy to read.

Buttons and feedback

Rounded sound buttons use consistent spacing, borders and corner radii. A filled background identifies the selected genre and atmosphere, while the small sound counter shows the recording selected within each category.

Play is the main action and sits in the centre of the player controls. Volume is visually smaller, while Random, Reset and Repeat are grouped as supporting actions.

Icons reduce the space needed for familiar actions such as playback, volume and theme switching. Accessible labels identify controls that do not have visible text.

Responsive behaviour

On larger screens, the sound categories use four columns. The playback area places volume, Play and the supporting controls across one row.

On smaller screens, the sound buttons change to two columns and the playback controls rearrange vertically. This keeps the buttons readable without squeezing every control into a narrow row.

Day and night modes provide an additional visual preference. Changing the theme does not change the selected sounds.

Testing and refinement

Balancing the player controls

Teacher feedback highlighted the balance of the lower interface, particularly the size of the intensity slider. I reduced its visual emphasis and changed it to a volume icon and slider, which better describes what the control actually changes.

I also moved Play to the centre so the main playback action has a clear position between volume and the supporting controls.

Explaining double-click

Peer testing showed that the click and double-click instructions were easy to miss. Enlarging the instruction alone did not make the interaction clear enough.

I introduced a short guide that appears on first use and can be reopened through a question-mark button. The guide presents one step at a time instead of showing a long block of instructions.

The sound buttons also support the right arrow key to move to the next recording when a button has keyboard focus.

Making feedback easier to read

Feedback also showed that “1 / 4” was unclear. I changed it to “Sound 1 / 4” to explain what the number represents.

A peer suggested moving the soundtrack display from the bottom to the top. This brings the current combination closer to the sound selections and makes the interface feel more connected.

Reflection

The main challenge was balancing a quiet reading interface with interactions that users could discover. Removing visible text made the page simpler, but also made the double-click interaction harder to understand. The step-by-step guide provides an explanation without keeping a long instruction on screen.

The final instrument gives readers a small set of meaningful choices. Controlled randomness adds variation, while persistent selections keep the reader in control of the overall atmosphere.

A limitation is that double-click is less familiar on touchscreens. A future version could provide a visible next-sound control. Audio transitions could also be refined with fades; these are not included in the current version.
